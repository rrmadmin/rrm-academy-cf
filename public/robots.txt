# Strategy: MAXIMUM AI VISIBILITY
# All public content is accessible to all crawlers -- search, training, and
# traditional. Private paths (auth, API, community, dev) blocked consistently.
#
# AI search crawlers (ChatGPT-User, Perplexity-User, etc.) fetch content in
# real time when users ask questions -- allowing them = appearing in AI answers.
#
# AI training crawlers (GPTBot, ClaudeBot, etc.) build future model knowledge.
# For a young site building authority, training inclusion = future visibility.
# To block training later, change their Allow: / to Disallow: /
# =============================================================================

# --- Content Signals (contentsignals.org / draft-romm-aipref-contentsignals) --
# Delivered BOTH ways: (1) the Content-Signal directive below, per the
# contentsignals.org spec (canonical robots.txt placement, what agent-readiness
# checkers validate), and (2) an HTTP response header on every response via
# functions/_middleware.js -> withSecurityHeaders(). Keep the two values in
# lockstep. History: directive removed 2026-05-15 because Lighthouse's
# robots.txt validator only understands the 1994 spec and flags unknown
# directives; re-added 2026-06-05 (ecosystem standardized on robots.txt
# placement; the Lighthouse nit is cosmetic). All signals = yes per the
# MAXIMUM AI VISIBILITY strategy above.

# pillars. Pattern requires a non-empty *second* segment after /courses/,
# so single-segment landings like /courses/aip-diet-inflammation/ are
# exempt (their match attempt fails because the URL has no trailing /
# beyond the slug). Verified live 2026-05-21.

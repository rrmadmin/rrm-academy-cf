01User flow

The whole point of the redesign is to make the operating model legible. A visitor should move from "what is this?" to "I have a job here" without a single dead end. The dashed line is the membership gate — everything left of the stream is the public recruiting surface; the conversation itself is members-only.

A

The structure renders server-side for logged-out visitors — the entire recruiting value prop. Requires the functions/_middleware.js carve-out (CRITICAL finding #1) and re-scoping the security-guard invariant. Data comes from public GET /api/community/{areas,projects,impact}. Gate G-AREA-4.

B

Owners shown by name, stored as owner_user_id. "Owner TBC" renders when the FK is NULL (unresolved) — never a dangling name string. Resolution is a separate idempotent UPDATE so a re-run backfills it. Gate G-AREA-8.

C

"This Month" is owner-curated in v1 (auto-counted events deferred to Phase 2 — no computable source exists yet). The month window is computed in America/New_York, not UTC. Gate G-AREA-11.

D

One consolidated stream, not 5 channels. With ~36 members, splitting into per-area rooms makes every room look dead. Area pills filter the single stream; the "All" view always includes untagged (NULL-area) posts. Gates G-AREA-1, G-AREA-7. Jenna's post (no chip) is an untagged post — still shows under All.

E

"Joined ✓" state survives a cold page load via GET /api/community/memberships (the missing read-back the deep trace caught — finding #7). Double-join is an idempotent no-op, not a 500. Gate G-AREA-2.

F

Tier badges (Lead, Founder) render natively in the stream — same primitive the live-calls spec uses. Member tiers come from existing community membership data.

G

The area page is a filtered lens, not a room. Same posts, same composer, scoped to area_id = research. This is why fragmentation never creates a dead room — every "channel" is a view over one shared stream. Gate G-AREA-7 (all child reads resolve through an active-parent join).

H

Paused/done projects stay listed but suppress the Join CTA; archived projects + archived areas drop out entirely. Archiving propagates as a state transition (area → its projects), so nothing strands pointing at a hidden parent. Findings #8, #15.

05What to evaluate

Decisions worth a gut-check

  • One stream + filter pills vs. per-area rooms. Mockup commits to one stream — does the filtered area view feel like enough structure?
  • 4 Action Areas (Research / Patient Advocacy / Education / Community). Right set? Right names? Recording 129 only firmly names Research → Bailey.
  • "This Month" curated-only in v1. Auto-counted impact is Phase 2 — acceptable, or does the strip feel thin without it?
  • Owners surfaced publicly. "Owner TBC" is honest but visible — fine on the recruiting page?
  • Logged-out sees structure. Is the gated-stream slot the right conversion moment, or should more/less be visible?

Open items before build

  • Confirm the Action Area set, taglines, icons, and real owner user IDs.
  • Decide if area detail pages are indexable (likely noindex until populated).
  • Workspace links: open in new tab; any access provisioning on join?
  • Should /save-the-uterus-club/ landing copy point at Action Areas as the "what you'll do" proof?
  • Coordinate migration number + posts.js DELETE edit with the live-calls spec.
  • Phase 2: define the auto-counted impact source query.

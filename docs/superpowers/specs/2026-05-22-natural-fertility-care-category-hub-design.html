Natural Fertility Care — Category Hub Page

One tightly-scoped category hub to win AI-search share of voice for the field — not a giant comparison.

1Problem

orank measures whether AI search engines associate a domain with its category. RRM Academy has deep entity/method pillars (/naprotechnology/, /femm/, /neofertility/, /what-is-rrm/) and condition pages (endo, PCOS, miscarriage, endometritis), but no asset that claims the category itself — "natural / restorative fertility and reproductive health education."

The failing gap: Category share of voice 0/6. For the query "natural fertility and reproductive health education platform", rrmacademy.org does not surface. FEMM Health, Natural Womanhood, and NaProTechnology dominate.

The tested query is a category/platform query, not a brand or method query. To surface for it, the site needs an entity-level page that defines the category and positions RRM Academy as the neutral education hub within it.

2Non-goals (YAGNI)

  • Not a giant all-in-one comparison page — diffuse intent, not cleanly extractable by LLMs, cannibalizes the method pillars. (Brian has built these before; they underperform.)
  • Not head-to-head competitor framing. Methods are treated on their merits, never as rivals. No "why we beat X."
  • Not a programmatic page set. One focused page first; measure before extending.
  • Not the "alternatives to IVF" spoke — deferred (see Future Work).

3Goal & success criteria

Publish one category hub with a single clear intent: what this field is, how the approaches compare, and where to learn / get care. One page answers the platform query and the "which method" query without a 5,000-word everything-dump.

Success = a follow-up orank rescan (POST https://ora.ai/api/scan {"url":"rrmacademy.org"}) shows the Category-share-of-voice line move off 0/6.

4Page design

URL: /natural-fertility-care/ (root-level, flat pillar IA). Vanity aliases 301 via rrm-router.

Byline: Dr. Naomi Whittaker (matches every pillar; written in her clinical voice via Gianna).

Length: ~1,800–2,200 words. Single intent — not an everything-dump.

Structure

  1. Definition lede. One extractable opening paragraph defining natural / restorative reproductive healthcare — the passage AI engines lift and cite. Principle-level only.
  2. Comparison module (the only comparison — scoped to a module, not the page):

Cells filled at build time from rrm-cli / library. Even-handed, evidence-based, no ranking-by-superiority.

  1. "How to choose" decision section. Short, question-shaped ("If you want X, start with Y"). No hard "yes" on outcomes.
  2. Where RRM Academy fits. The neutral education hub above all methods. Internal links to /what-is-rrm/, /femm/, /naprotechnology/, /neofertility/, and condition pages.
  3. FAQ block. 4–6 real use-case questions ("Is there a natural alternative to IVF?", "Which method is most accurate?", "Can natural methods treat the cause of infertility?"). Answers lead with "In many cases…", never a bare "Yes."

Schema (JSON-LD @graph)

  • CollectionPage + MedicalWebPage
  • ItemList enumerating the six methods (per-method AEO)
  • FAQPage for the FAQ block
  • BreadcrumbList (Home → Guides → Natural Fertility Care) via buildBreadcrumbList()
  • author = #naomi-whittaker, isPartOf = #organization via identity graph helpers

5Content sourcing & compliance

  • Clinical facts grounded via rrm-cli against D1 rrm-library; verify any statistic against a primary source.
  • Prose written through Gianna in Dr. Whittaker's clinical voice.
  • Hard rules: principle-level RRM claims only; method-specific claims attributed to the named method; no Hilgers protocols/dosing on public pages; no hard "yes" on fertility questions; no em dashes.

6Wiring (registry + routing)

Built via the /pillar-create skill so all Gate 11.5 surfaces update together:

  1. ssot/pillars.json — new pillar entry; flows into 6 consumers (guides catalogue, library-sitemaps PILLAR_PATHS, AppShellChrome GUIDES_PATHS, BaseLayout navigate_to_section, build-guides-data, build-og-index).
  2. src/pages/natural-fertility-care/index.astro — BaseLayout + MaybeShell + SectionTocChips, following pillar conventions.
  3. rrm-router ASTRO_ROUTES (separate repo) — add /natural-fertility-care.
  4. OG card — auto via build-og-index.mjs; verify /og/natural-fertility-care.png renders.
  5. CI gate scripts/gates/validate-pillar-registry.mjs must pass.

7Verification

  • npm run check-types and npm run ssot:validate clean before push.
  • Build locally; JSON-LD validates; comparison table mobile-responsive (393×852 Playwright screenshot).
  • After deploy: https://rrmacademy.org/natural-fertility-care/ returns 200, appears in guides catalogue + sitemap.
  • npm run embed so semantic search indexes the new content.
  • Follow-up orank rescan to confirm Category-share-of-voice improves.

8Future work (deferred)

If the hub ranks, add one single-intent spoke: "Natural & restorative alternatives to IVF" — framed as root-cause-first, complementary care (not "skip IVF"), honoring the no-hard-yes and no-prescriptive-field-claims rules.

9Revert

Single page + one pillar-registry entry + one router-route line. Revert = remove the pillar entry, delete the page directory, drop the ASTRO_ROUTES line. No data migrations, no schema changes.
